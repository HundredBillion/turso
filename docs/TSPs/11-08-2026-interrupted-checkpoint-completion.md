# Complete an interrupted shared checkpoint without admitting a partial Store

Status: parent-approved private implementation plan; normal-bootstrap peer independently reviewed the continuation interface. Builds on the approved interrupted physical-WAL recovery plan and the verified normal completed-checkpoint confirmation/finalization/reclamation work. Public mode remains disabled until integration and PHP acceptance pass.

## Outcome and invariants

Consume the actual `RecoveredIntentPhysicalBase`, preserve its original runtime, selected INTENT, original open configuration, publication lease and admission pause, and finish the acknowledged checkpoint. An ACK physical base needs real target-ID preparation and durable completed records. A SOURCE physical base additionally needs one actual private Store, bounded replay of the acknowledged logical prefix and actual materialization. Both paths must eventually enter the verified normal completion chain and produce a usable Database containing every acknowledged row.

Never manufacture a Normal record for a replay API, infer a completed proof from a timestamp, clear mapped recovery to make an ordinary helper work, reset the Runtime's permanent Store claim, or construct a second Store after SOURCE replay. No changes to the disk format or the approved public policy are proposed.

Source references inspected in the normal-bootstrap worktree:

- `shared_store_claim.rs`: `Free -> Reserved -> Attached`; generic attachment and fresh reclamation reserve only a Free Runtime. Attached is permanent.
- `shared_checkpoint_recovery_reclaim.rs`: `begin_log_reclamation` currently always reserves a fresh Store before truncating the retained logical log.
- `shared_checkpoint_recovery_bootstrap.rs`: `prepare_store` constructs from that reservation; the final evidence already verifies actual Store/Runtime/config/Database identity, schema, target frontiers, original connection, retired I/O and the real completed proof before exposing replay and releasing admission.
- `shared_refresh.rs`: ordinary refresh rejects INTENT, validates the bounded log salt/CRC/endpoint/timestamps and imports prepared frames; its tail recovers mapped state. The new path must reuse frame mechanics without calling that ordinary tail.
- `checkpoint_state_machine.rs`: normal shared authorization uses `validate_oracle_identity`, and its normal materialized proof checks `guard.published()`. Both must remain strict. The actual materializer already supports retaining the logical log and FULL/TRUNCATE.
- `shared_ids/checkpoint_prepare.rs`: ordinary preparation requires `guard.published()` and finalized source selectors. It cannot be called on an unrecovered intent by silently recovering the guard.
- `checkpoint_publication.rs`: ordinary completion likewise requires published source-prefix authority plus live materialization and prepared-ID evidence. A separate sealed recovery adapter is necessary.

## Ownership and interfaces

### Common intent owner

`RecoveredIntentPhysicalBase` is the only entry. Its physical parts choose SOURCE or ACK by exact values already verified against the real INTENT; no caller-supplied timestamp/config replacement is accepted. Integrate `Arc<RecoveryOpenConfig>` once from the original options and carry the same Arc throughout. Fresh manifest selections must use the actual retained manifest Arc/native identity and the original lease. Actual main/WAL/layout evidence must be revalidated before each mutation and after yielded I/O. Content-readonly recovery remains a clear error.

### SOURCE-only Store owner

Introduce an opaque, non-Clone `IntentRecoveryStore` in the recovery child. Its constructor consumes a genuine fresh `SharedStoreReservation` while the original intent is held, constructs exactly one `Arc<MvStore>` using the actual config allocator and runtime storage, and records that exact Store, Runtime, config, source identity and publication lease. The consumed fresh constructor installs an opaque SourceStoreLifetime as the final actual MvStore field, containing a strong actual PublicationLease Arc. Ordinary new_in initializes no lifetime; only the sealed intent constructor can construct the token. This is not an IoPin: it preserves native exclusion when a consuming callee destroys the original guard first, including when a private factory/backend retains a real Store clone. Lease destruction follows the LAST actual Store data destruction, without preventing I/O retirement or changing explicit guard.finish after Ready checks. There is no lease getter, reactivation method or generic existing-Store attachment path. No constructor accepts a generic existing Store. No setter converts Attached back to Free or relabels an ordinary Store as recovery-owned.

The owner is carried through replay, materialization, real Normal completion, fresh normal selection, physical/ID confirmation, ID finalization, log reclamation and final local installation. While the owner exists, runtime replay stays None; no public Database/connection escapes. Every resume checks actual Store pointer, Runtime pointer, config Arc, lease, no local transactions and actual selected intent/completed identity. All owner/state fields and explicit abort paths destroy private source/materialization connections, pagers and Store references before the original guard and pause. Backend operations retain the publication/physical ownership needed through their actual retirement; late callbacks must not reopen admission. Dropping a failed owner is fail-closed; asynchronous backend completion keeps its authority until retirement. A retry that cannot retain that exact owner reconstructs through a fresh Runtime after the old owner and I/O have gone, rather than resetting Attached.

### Disjoint reclamation continuation

Carry a private `RecoveryStoreContinuation` through the normal recovery owners:

- `Fresh`: the existing normal/ACK path. `begin_log_reclamation` retains its present `reserve_store` requirement and stale/preexisting-Store rejection.
- `Owned(IntentRecoveryStore)`: constructible only by the sealed SOURCE path. At reclamation, validate its exact Store/Runtime/config/lease and completed target instead of reserving another Store. At final bootstrap, extract the same actual Store instead of calling `construct_store`.

This enum is not a public flag and has no conversion from an arbitrary Arc<Store>. Ordinary normal selection initializes Fresh. Only the genuine intent completion owner can attach Owned to a fresh selection of the real completed records. The actual guard/pause/physical parts remain continuously owned while this continuation moves through existing confirmation states.

Before final Ready, close and destroy the private source/materialization connections and pagers, verify their outstanding I/O is retired and no local transaction remains, then construct the final Database around the same Store. Capture and validate the actual Store frontier and source map/schema generations before preparing the final reload: replay/materialization may already have advanced them to ACK. Never substitute an assumed SOURCE frontier or reset Attached. Install the real completed physical maps/schema, reset/certify the final actual pager, reconcile the actual reclaimed append offset/CRC/header, and use the normal final evidence checks. Native callbacks must retain the original ownership during cancellation. Public admission is last, after `guard.finish()` succeeds; finish error withdraws replay as in the existing chain.

## Bounded SOURCE factory and materializer seam (parent review before behavior)

The first SOURCE-ID operation reuses `IdLoad`: its real backend read completion already retains both its `ownership` Arc containing the unique guard and an IoPin, and loading waits for retirement before returning LoadedIds. A new `inspect_intent_source` adapter accepts an opaque evidence object produced only from the actual SourceIntentStore and the real mirrored intent. The known source identity is `(record.log_generation, intent.source_checkpoint_timestamp, record.prefix)`; no target-minus-one or mapped prefix. The adapter suspends the actual mirrored intent internally, retains its token and pause, and keeps LoadedSourceIds opaque. It exposes borrowed guard/floor/epoch facts, not ordinary mutation/rejoin or a Normal manifest. SOURCE rejects a prepared target inconsistent with its still-SOURCE main. Only those actual facts may lower the empty Store's allocation bounds and permit construction/replay.

Before the first private SOURCE main/WAL read, reacquire all native physical byte locks on the actual Runtime mapping under the original publication guard and pause. Reconfirm the actual selected INTENT and native file identities. Retain those same physical locks through factory header/WAL initialization, bounded replay, materializer reads/writes, WAL/full-main barriers, WAL truncation, fresh ACK parse, final derived mapping repair and coordination FULL sync. Do not release at the factory or replay boundary.

The actual-Store lifetime token must retain private physical ownership while a source connection/pager can exist, as well as publication ownership. Source state owns bindings outside that token to avoid an owner/binding cycle. Every real main/WAL backend completion retains the existing typed physical/publication capture. On cancellation, dropping the state, waiter or original guard cannot release either native exclusion while a backend or a private Store/connection/pager alias survives. This is stronger than dropping the state's physical Arc. The token drops physical ownership before publication ownership. It has no public getter or reactivation API.

After actual materialization and its durability/read-retirement evidence, destroy private source connection, pager and Database objects and verify their actual Weak references are dead. Only then may the sealed source phase remove its token's physical ownership and proceed through target IDs/two Normal records/fresh normal confirmation. Any surviving private alias yields bounded BUSY while ownership is retained; a cancelled run stays excluded until the aliases and real backends die. The final normal factory continues to use normal mapped coordination and the same actual Store. Its Ready release remains the only explicit successful publication unlock.

The factory cannot simply reuse completed-bootstrap evidence. Add a separate SourceConstructionEvidence after real ID inspection, binding the exact Store/config/Runtime/lease/source header/native files and physical owner. Its private constructor/permit path may reuse ordinary Database allocation and header-validation mechanics, but never supply a CompletedCheckpointProof or set Normal state. It returns only private staging ownership. A Source permit must select InProcessWal and reject mapped coordination for that exact private Database throughout initialization, metadata/debug paths and destruction. Otherwise `Database::open_shared_wal_coordination_inner` returns `runtime.physical_coordination()` whenever a Runtime is attached, and `build_wal` constructs the mapped implementation; holding native recovery locks would then conflict with ordinary writer/read acquisition. The source policy must be derived from the opaque permit, not a caller flag. Normal completed permits/factories keep their existing behavior.

Admission audit of the intended helpers:

- `Connection::compile_cmd` invokes `refresh_shared_schema_for_prepare` for ordinary root statements with no transaction. - `prepare_recovery_frame` stages sqlite_schema/custom-type records, calls `recover_build_schema`, and decodes row/index changes without preparing/executing SQL. `recover_build_schema` uses schema-row parsers and symbols/dialect/qualifier reads. `prepare_peer_sequence_schema` derives descriptors from actual prepared row records. Reuse these pure paths; preserve their staged schema and sequence semantics.
- `install_peer_frame` imports prepared versions/root maps and schema under its clock publication, without transaction admission or SQL. Drive it only under the sealed SOURCE state and original authority; never invoke SharedRefresh's normal mapped-recovery/admission tail.
- `CheckpointStateMachine`/`BuildLocalSchemaViewStateMachine` use BTree cursors, committed-version overlays and pager transactions directly; they do not call Connection.prepare/query/execute. - `Connection::drop` rolls back any transaction and releases its WAL locks; Database::drop removes its registry entry. Source cancellation uses private ownership destruction, not a public close/checkpoint operation. Required native tests before this seam is accepted: original source header/ID facts before any logical allocation; real CRC/endpoint/salt replay and DDL/sequence frames without shared-admission reentry; cancellation before/after factory physical callbacks and materializer barriers with a real private connection/pager/Store alias; direct new native physical/publication participants remain BUSY until last alias/backend retirement; normal Source connection SQL remains fenced; actual acknowledged data survives required-page omission controls; normal Fresh/Completed factories and foreign-runtime/config/lease rejection remain unchanged.

A private pager alias does not necessarily retain its Store. Therefore the physical-stage ownership must also be retained by private main/WAL File facades (and their permits), not only by the Store token. Each facade owns its own GuardedFile/read-pinned binding for its entire lifetime, with read pinning enabled; cancellation cannot clear that binding while a pager still owns the facade. Facades, actual Store lifetime and active source state share an opaque phase lease containing physical-before-publication ownership.
